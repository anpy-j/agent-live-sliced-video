# LiveCut Agent

通过已连接的 `live-slicer` MCP 服务管理直播切片。Agent 只负责不能由程序可靠完成的创意判断；本地服务负责转写、两层文本筛查、时间线校验、受控多模态混剪和一次高清渲染。

## 工作方式

1. 调用 `create_video_job` 创建任务，保留返回的 `job_id`。
2. 使用 `get_video_job` 查看整体节点。运行中时不要重复创建任务。
3. 状态为 `waiting_input` 时调用 `get_stage_packet`，只读取当前节点所需的精简材料，不回读完整日志。
4. 创建任务可传 `subtitle_path`、`delivery_mode` (`merged`/`segments`) 和 `creative_strategy` (`auto/selling/tryon/personality/story/visual`)。有效字幕跳过全片 ASR；`auto` 根据素材选择最成立的方向，不强套固定销售模板。
5. 优先把完整口播安全拆到 1.2–10 秒；无可靠安全边界时允许最长 18 秒的完整声音单元，画面仍独立切成最长约 3 秒镜头。`safe_standalone=false` 的候选必须通过递归依赖闭包与 `required_atom_ids` 紧邻成组选择，不得单选；缺失依赖和环一律失效。
6. 编排至少比较两个方向；多个 `hook_*` 是独立版本，必须分别按 `hook_A + body`、`hook_B + body` 审核并选择，禁止把多个 hook 串播评分。高清渲染前先检查源时间戳，再对实际生成的低码率音频预览执行二次 ASR 和连接点检查。
7. `completed` 表示任务已交付；`publish_ready=true` 才表示文案、切点和技术 QC 全部通过。任何 AI 失败都走确定性降级，不进入人工等待。
5. `edit_plan`：理解本地脚本筛选后的 40–80 条候选，只返回 `candidate_id/role/module/product/color` 和本版 `creative_strategy`。第一轮选主方案；只有硬错误或时长确实不足时，最多两轮只从未使用候选补充。候选的 `u` 是同源历史使用次数，优先 `u=0`，素材不足时允许保留不可替代的强句。
6. 系统使用同一共享规则做 AI 预检与引擎终检。约 90 秒是软目标；近义重复、面料最多一次、违禁和错商品是硬门禁。proof、close、购买引导和固定角色顺序不是硬要求；优先安全拆分，必要时允许最长 18 秒的完整自然表达，不为制造节奏强行打碎。
7. 先局部检查最终入选画面；全部正常立即结束。坏画面只在前后 90 秒内寻找同商品、同颜色候选，每段最多六个。正面嘴部清晰时禁止异时画面配原声，无法确认就保留原始同步画面。两种交付模式均附带按成片时间重排的 SRT；`merged` 只启动一个合并编码，`segments` 不生成合并视频。
8. 反馈必须选择正确作用域：文案/重复问题用 `text`，错款错色/构图用 `vision`，编码速度或画质用 `render`。三个域不会互相注入。
9. 提交后继续查询同一任务，直到完成或失败。失败时先读取当前节点错误，不盲目重建任务。

同一个源素材可以重复创建任务：系统会把每次剪辑放进独立的 `edits/<任务ID>-<成片名>`；公共字幕/ASR 索引按指纹复用，素材级历史账本对上一版用过的策略、原句和时间范围降权，避免只换文件名不换内容。不得把上一任务的 picks、时间线、视觉决策或成片当成本任务结果。

## 可选偏好

任务中的 `optional_editing_preferences` 仅补充时长、节奏、重点卖点等创意偏好。它不是必填项，也不改变五阶段主流程；为空时直接按本 Skill 的创作边界判断。

## 创作边界

- 不为凑时长保留重复或弱内容；时长是目标，不是填充要求。
- 原声必须可追溯，不通过拼接制造原本不存在的事实、因果或承诺。
- 文本编排不接收图片；多模态模型仅在混剪节点选择替换画面，标准是同款衣服、清晰、站立全身或大半身，不要求动作与文案逐字匹配。
- 优先利用主播独特表达、动作和临场情绪，不机械套用固定钩子结构。
- 完整进度与产物以本地工作台为准，不依赖对话上下文保存状态。
- 任务标题就是最终 MP4 文件名；创作时不要擅自改名。
