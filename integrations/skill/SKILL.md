# LiveCut Agent

通过已连接的 `live-slicer` MCP 服务管理直播切片。Agent 只负责不能由程序可靠完成的创意判断；本地服务负责转写、缓存、时间线校验、画面一致性检查、渲染和质检。

## 工作方式

1. 调用 `create_video_job` 创建任务，保留返回的 `job_id`。
2. 使用 `get_video_job` 查看整体节点。运行中时不要重复创建任务。
3. 状态为 `waiting_input` 时调用 `get_stage_packet`，只读取当前节点所需的精简材料，不回读完整日志。
4. `edit_plan`：理解素材后只选择一个最强成片方向，默认生成一个钩子；提交 `main_product` 和 `picks`。除非用户明确要求，不并行生成近似方案。
5. 系统自动完成时间线、边界、画面结构规则校验和低清粗剪。不要再对联系表做一轮独立模型审核；商品/颜色等语义是否正确，统一在实际粗剪中检查。
6. `rough_cut`：审看实际粗剪视频；可发布时提交 `{"verdict":"approve"}`，随后系统高清导出并执行完整 QC。
7. 提交后继续查询同一任务，直到完成或失败。失败时先读取当前节点错误，不盲目重建任务。

## 可选偏好

任务中的 `optional_editing_preferences` 仅补充时长、节奏、重点卖点等创意偏好。它不是必填项，也不改变五阶段主流程；为空时直接按本 Skill 的创作边界判断。

## 创作边界

- 不为凑时长保留重复或弱内容；时长是目标，不是填充要求。
- 原声必须可追溯，不通过拼接制造原本不存在的事实、因果或承诺。
- 声音与画面可以解耦，但具体颜色、版型、材质和商品身份必须相容。
- 优先利用主播独特表达、动作和临场情绪，不机械套用固定钩子结构。
- 完整进度与产物以本地工作台为准，不依赖对话上下文保存状态。
- 任务标题就是最终 MP4 文件名；创作时不要擅自改名。
